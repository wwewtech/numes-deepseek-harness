# Numes в DeepSeek Harness — полная установка

**Цель:** получить в DSH модели Numes через штатный адаптер `llm-pi-ai`, а бесплатный маршрут — только через `author/model:free`.

**Установка как бандл (рекомендуем для новых установок):**
```
dsh plugin --profile desktop add github:wwewtech/numes-deepseek-harness
```
Затем запустите прокси (`node tools/numes-free-failover.mjs`) и выберите предзарегистрированный провайдер `numes-free` в пикере моделей. Ручной способ ниже эквивалентен, просто дольше.

Инструкция проверена на **DSH Desktop 0.2.2-rc.3, Windows, USD-ключе Numes, 17 ноября 2026 года**. Повторная проверка 18 ноября 2026 года: в DSH rc.4/rc.5 изменились только серверный поиск и исправления ошибок — процесс настройки провайдера и работа с ключами, описанные ниже, не изменились. Изменения в работающий профиль делаются **не автоматически** — только действия пользователя в GUI. Репозиторий неофициальный, не требует установки как бандл DSH.

> Если вы уже установили DSH и есть ключ Numes, начните с [шага 3](#3-создайте-inference-ключ).
> Если маршрут уже настроен, но был `QUOTA`/`402`, сразу читайте [раздел про суффикс `:free`](#5-выберите-бесплатные-модели).
> Хотите быстрый трек? `dsh plugin add github:wwewtech/numes-deepseek-harness`, запуск прокси, выбор `numes-free`. Готово.

## 0. Что понадобится

- DSH Desktop или `dsh web` с рабочим интерфейсом **Settings → Models**.
- Ваш аккаунт Numes, зарегистрированный самостоятельно на [numes.ai](https://numes.ai).
- Для бесплатных запросов — подтверждённый email. Проверьте [Profile](https://numes.ai/dashboard/profile), если получаете `403 verified_email_required`.
- Свой **inference-ключ** Numes, который вы храните локально. Не публикуйте ключ и не отправляйте его в issues.
- Подключение к интернету. **Покупать кредиты для использования `:free` не нужно** — когда такие предложения есть и у них есть свободная квота.

**НЕ требуются:** плагин `our-free-model`, отдельный репозиторий Numes, пакет `openai`, локальный прокси, постоянный HTTP-туннель, баланс `$10+`.

## 1. Установите и запустите DSH

### Вариант A — уже установлен DSH Desktop

Откройте существующее приложение. Версию диагностики можно найти в настройках/окне About, если она отличается от указанной выше.

### Вариант B — официальная команда запуска Web UI

Следуйте актуальному [официальному README DSH](https://github.com/deepseek-ai/deepseek-harness#run). На момент написания:

```sh
npx @deepseek-ai/dsh web
```

Нужен подходящий Node.js — проверьте текущие системные требования по ссылке выше, не стройте установку по старому номеру версии.

Команда запускается **из папки вашего проекта**: приложение использует директорию вызова как исходное рабочее место. По умолчанию локальному Web UI открывается `http://127.0.0.1:3080` (или URL, который напечатает ваша версия). Не заходите на чужой аналогичный адрес.

Если есть уже запущенный DSH, **не поднимайте второй сервер, чтобы «обновить» GUI**: настраивайте существующий процесс по его адресу.

[Официальный гайд по Web UI](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/index.md) дополнительно рекомендует **Choose workspace** прежде, чем отправлять задачу агенту. Для настройки модели пока достаточно Settings.

## 2. Зайдите в аккаунт Numes и проверьте email

В [Numes](https://numes.ai) пройдите обычные Sign up / Sign in. Если email ещё не подтверждён, откройте письмо от сервиса и подтвердите его — бесплатные вызовы этого требуют.

Создание множества аккаунтов, автоматическая регистрация/кэпча и обход лимитов здесь **не описываются и не нужны**. Для одного пользователя достаточно одного аккаунта, одного ключa на каждое приложение и окружение.

## 3. Создайте inference-ключ

1. Откройте [Dashboard → Keys](https://numes.ai/dashboard/keys).
2. При необходимости выберите правильный аккаунт в переключателе аккаунтов.
3. **Create key**.
4. Укажите понятное **Name**, например `dsh-desktop`.
5. **Type → Inference** — именно он может вызывать модели. Management-ключ для этого не подходит.
6. Выберите **Currency**, например **USD**. Валюта не меняется после создания.
7. Опционально установите **Spend limit** и период сброса. Хоть `:free` не должен списывать, лимит пригодится, если позже добавите платную модель.
8. Нажмите **Create key** и скопируйте секрет из окна **Save this key now**.

Секрет показывается один раз. После закрытия окна восстановить его нельзя — создаётся новый ключ. Не публикуйте его в Git, prompt, issue и скриншоты.

[Официальные правила создания и ротации ключей](https://numes.ai/docs/account/api-keys).

## 4. Добавьте Numes в DSH через GUI — рекомендуемый способ

1. В DSH: **Settings → Models**.
2. Нажмите **Add model provider**.
3. Переключитесь на **Custom model API**.
   Не выбирайте `Third-party model provider` и не ищите готовый `numes` preset: маршрут определяем самостоятельно.
4. Заполните форму **точно**:

   | Поле | Значение |
   |---|---|
   | Provider ID | `numes` |
   | Display name | `Numes` (необязательное отображаемое название) |
   | Base URL / Endpoint | `https://api.numes.ai/api/v1` |
   | API protocol | `OpenAI Chat Completions` |
   | API key | ваш inference-ключ |

5. Сохраните форму кнопкой **Create/Apply**, если ваш release требует её нажать перед discovery. Если discovery доступно на самой форме нового провайдера, можно продолжить прямо с неё.

**Протокол важен:** не `OpenAI Responses`, не `Anthropic Messages`, не `Gemini API`. Numes здесь работает через `POST https://api.numes.ai/api/v1/chat/completions`.

`Provider ID` останется в настройках и выборе моделей. Если по какой-то причине он уже занят другим вашим маршрутом, выберите другой, например `numes-free`; дальнейшие примеры используют именно `numes`.

### Что произойдёт с ключом

DSH сохранит его **write-only** в credential store и в патче оставит только ссылку `NUMES_API_KEY`. Полный ключ не возвращается в браузер: вы увидите маскированное превью/зелёный индикатор сохранённого секрета.

В стандартной локальной конфигурации это `$DSH_HOME/.credentials.yaml`. Не переносите сюда секретные поля вручную, если работаете через GUI.

## 5. Выберите бесплатные модели

1. На карточке провайдера нажмите **Fetch available models**.
2. Дождитесь получения каталога `GET /models`. Это загрузка списка, **не тест ответа модели и не доказательство $0**.
3. Найдите модели, у которых ID заканчивается на `:free`.
4. Отметьте их поодиночке либо используйте **Select all для отфильтрованного списка**, если выбор действительно состоит только из нужных предложений.
5. Нажмите **Update list**, затем **Apply/Create** у карточки провайдера.

Рекомендуемая первая модель: `moonshotai/kimi-k3.1-pro:free`.

### На момент 17 ноября 2026: 9 таких ID

```text
moonshotai/kimi-k3.1-pro:free
deepseek/deepseek-v4.1-flash:free
z-ai/glm-5.3:free
z-ai/glm-5.3-flash:free
nvidia/nemotron-3-ultra-550b-a55b:free
dealignai/deepseek-v4.1-flash-uncensored-fp8:free
dealignai/glm-5.3-flash-uncensored-fp8:free
dealignai/glm-5.3-uncensored-fp8:free
uniboshi/kimi-k3-abliterated-v1:free
```

Это список **утверждающийся только на указанную дату**; выбирайте актуальные ID из живого каталога. Если модели в списке нет, самостоятельно придумывать `:free` не поможет: в таком случае он вернётся как недоступный, а не как «вечно бесплатный тариф».

Если кнопка не появилась или discovery ничего не получил, введите ID вручную в каталог моделей провайдера. **Для ручного сохранения укажите актуальные `contextWindow` и `maxTokens` согласно `GET /models/...:free/endpoints`.** Приведённые 1 048 576 / 65 536 (у GLM 5.3 — 262 144 / 65 536) также датированное измерение 17 ноября и не должны молча применяться спустя месяцы. Информация об endpoint'e может измениться вместе с его предложением.

### Почему важно именно окончание ID с `:free`

В современной логике Numes:

| ID | Какие endpoint'ы выделяются |
|---|---|
| `author/model` | только с ценой |
| `author/model:free` | только где все ставки нулевые в валюте ключа |

`:free` **документированно** не переходит к платному endpoint. При отсутствии доступных бесплатных терминалов он возвращает `503 provider_unavailable` и ничего не списывает. Этим он лучше самодельного ограничения `prompt/completion = 0`.

Мои фактические проверки 17 ноября:

```text
Kimi K3.1 Pro:free → HTTP 200 → PONG → cost 0
Kimi K3.1 Pro      → 402 insufficient_credits на балансе 0 USD
```

Нулевая стоимость не равна «безлимит» и не обещает скорости или отсутствия логгирования. Читайте [Free models](https://numes.ai/docs/models#free-models) и [политику данных провайдеров](https://numes.ai/docs/privacy/provider-data-policies).

## 6. Выберите workspace, модель и проверьте работу

1. Если композер недоступен: **Choose workspace** и откройте ваш проект.
2. Рядом с полем ввода откройте пикер моделей (или используйте `/model`, если текущий GUI его показывает).
3. Выберите **Numes → Kimi K3.1 Pro (free)**. Форма обычно выглядит:
   ```text
   numes / moonshotai/kimi-k3.1-pro:free
   ```
4. Отправьте пробную короткую задачу:
   ```text
   Ответь ровно одним словом: PONG
   ```
5. Ожидайте ответ. Не нажимайте повтор после 2–3 секунд ожидания: у отдельных тестов первый токен шёл **50–85 секунд**, а короткие запросы в другом окне — около 3 секунд. Для tool-вызовов время может быть ещё больше.
6. Затем дайте маленькую безопасную задачу агенту, которая не требует опасных действий:
   ```text
   Скажи, какие из основных файлов есть в корне workspace.
   ```

Выбор модели в DSH делает её стандартом для новых сессий. **Уже существующая сессия после первого запроса сохраняет свою записанную модель** — если в ней была выбрана платная ID раньше, смените её в этой же сессии в пикере или создайте новую.

## 7. Где проверять цену и реальный endpoint

В DSH не считайте стоимость по имени в списке: маркетплейс выбирает фактический маршрут.

Откройте [Numes Activity/Logs](https://numes.ai/dashboard/logs) или формируете данные вручную через API.

Usage о балансе и лимите:

```powershell
$H = @{ Authorization = "Bearer $env:NUMES_API_KEY" }
Invoke-RestMethod "https://api.numes.ai/api/v1/key" -Headers $H
```

Пробный API-запрос:

```powershell
$H = @{
  Authorization = "Bearer $env:NUMES_API_KEY"
  "Content-Type" = "application/json"
}
$body = @{
  model = "moonshotai/kimi-k3.1-pro:free"
  messages = @(@{ role = "user"; content = "Reply with exactly PONG" })
  max_tokens = 1500
  reasoning = @{ effort = "none" }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod "https://api.numes.ai/api/v1/chat/completions" `
  -Method Post -Headers $H -Body $body -TimeoutSec 300
```

В выводе проверяйте `usage.cost`, `provider`, `model`. Ключ не выводите в логи и не сохраняйте в публичных заметках.

## 8. Альтернатива GUI: ручная настройка профиля DSH

Эта часть **не обязательна**. Сначала выберите вариант GUI, если вы не готовы редактировать YAML реального профиля.

### 8.1. Узнайте свой профиль и путь

Локальная папка DSH задаётся `$DSH_HOME`, по умолчанию обычно `~/.dsh` (`C:\Users\<имя>\.dsh` на Windows). Путь профиля:

```text
$DSH_HOME/profiles/<profile>/cordis.patch.yml
```

Для Desktop preview, проверенного мною, это был `profiles/desktop`; официальная документация `dsh web` использует `profiles/web`. **Не копируйте имя профиля по шаблону — уточните свою запускаемую конфигурацию.**

### 8.2. Сохраните бэкап текущей конфигурации

Перед любыми правками сделайте отдельную копию именно вашего файла, не замещая старые резервные копии:

```powershell
# Пример для Desktop, проверьте собственный профиль перед запуском:
$profile = Join-Path $env:USERPROFILE ".dsh\profiles\desktop"
Copy-Item (Join-Path $profile "cordis.patch.yml") `
  (Join-Path $profile "cordis.patch.yml.before-numes")
```

Если файла нет, **остановитесь**: не создавайте наугад всю структуру профиля, используйте GUI или создайте правильный профиль.

### 8.3. Добавьте только маршрут

Возьмите содержимое [`../configs/numes.patch.yml`](../configs/numes.patch.yml) и добавьте его блок в массив уже существующего `cordis.patch.yml`, сохраняя старые записи. Ключевая форма:

```yaml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      numes:
        displayName: Numes
        api: openai-completions
        baseURL: https://api.numes.ai/api/v1
        apiKeyEnv: NUMES_API_KEY
        streamIdleTimeoutMs: 300000
        models:
          - id: moonshotai/kimi-k3.1-pro:free
            name: Kimi K3.1 Pro (free)
            contextWindow: 1048576
            maxTokens: 65536
            reasoningEfforts: false
```

**Не замещайте** содержимое активного файла примером целиком: вы можете потерять настройки агентов и других провайдеров.

`streamIdleTimeoutMs: 300000` — заданный в адаптере интервал ожидания стрима (300 секунд), не способ ускорить бесплатный endpoint.

### 8.4. Положите свой ключ

Предпочтительно сохранить ключ через Settings → Models и сохранить только ссылку `apiKeyEnv: NUMES_API_KEY` в конфиге.

Альтернатива — `NUMES_API_KEY` в окружении процесса при запуске. Новая переменная, созданная уже после запуска, не попадает в ранее захваченный снимок окружения DSH.

Если редактируете локальное хранилище вручную, сначала прочтите [официальную спецификацию credentials-local](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/credentials/credentials-local/README.md). Оно является файлом с секретами в открытом виде: сохраняйте существующие `version: 1` и `records: ...`, а `refs` не заменяйте целиком:

```yaml
version: 1
refs:
  NUMES_API_KEY: "ВАШ_ОДИН_КЛЮЧ_ЛОКАЛЬНО"
# Сохраните также ваши существующие записи records без изменений.
```

Не комитьте этот файл в этот/другой публичный репозиторий и не обсуждайте его содержимое в issues.

При наличии локально сохранённого значения `refs` **оно имеет высший приоритет над переменной среды**: если ключ `.credentials.yaml` устарел, меняйте его через GUI (или аккуратная ручная правка по документации), а не только `$env:NUMES_API_KEY`.

### 8.5. Перезапускать или нет?

Официальный гайд DSH говорит, что изменения models/профиля перечитываются **по следующему запросу**, без перезапуска процесса. `dsh-hmr` следит за профилем, credentials-local следит за файлом.

Если в интерфейсе изменений не видно:

1. Обновите страницу GUI (F5) — это **существующий адрес**, не создание второго сервера.
2. Проверьте диагностику/журналы настроек DSH на ошибку YAML.
3. Если изменений всё ещё нет, полностью закройте Desktop и откройте его ещё раз. Один процесс DSH — ваш единственный процесс.

## 9. Если появляется `QUOTA`, `402` и т. п.

DSH может показать короткое `QUOTA`, а конкретный код оригинального ответа Numes иметь более полезный контекст. Используйте [официальный справочник ошибок](https://numes.ai/docs/api-reference/errors).

| Ошибка | Что код означает и первый шаг |
|---|---|
| **`QUOTA`/`402 insufficient_credits`** | На моём случае причиной был **plain ID без `:free`** после разделения free/paid каталога. Проверьте и **измените сам выбранный ID** в собранном провайдере и в чате. Пополнение не исправляет выбранную бесплатность платного маршрута. |
| **`429 rate_limited`** | У бесплатных запросов собственные лимиты. Ждите секунды из `Retry-After`; без него — экспоненциальный backoff/jitter. Числовой размер квоты проверяйте на свой ключ/API — в публичных доках не гарантируется. |
| **`429 provider_overloaded`** | Заполнена конкурентность upstream/worker. Меньше параллельности и backoff. |
| **`503 provider_unavailable`** | Теперь нет бесплатного endpoint (`:free` не переходит на платный), запрошено неподдерживаемое свойство/model ID не найден, либо фильтры/param constraints исключили предложения. Повторите discovery, попробуйте другую бесплатную модель. |
| **`401 invalid_credentials`** | Management вместо Inference, удалённый/disabled/expired ключ или неверный auth header. Не повторяйте один и тот же 401 ключ в цикле. |
| **`403 verified_email_required`** | Подтвердите email в профиле Numes. |
| **Пустой response/обрезанный finish** | Увеличьте `max_tokens`; reasoning-токены тоже идут в бюджет завершения. Для ручных проб начинайте с 1500+ и `reasoning.effort=none`, если endpoint разрешает это; не заказывайте необоснованно большие генерации. |
| **Не показываются модели в пикере** | Проверьте key and route, повторите discovery и сохраните поставщика. Некоторые модели могли выйти из каталога: `:free` не «прошивает» предложение навсегда. |

Для мелких падений стрима после частичного ответа обрабатывайте частичный текст/результаты tool calls отдельно. Не проигрывайте автоматические side effects повторно «как будто первый запрос не произошёл».

Для обращения в поддержку Numes указывайте **`X-Request-Id`** вместо ключа и полного приватного prompt.

## 10. Откат: удалить только Numes, остальное не трогать

### GUI

1. **Settings → Models → карточка Numes**.
2. Откройте редактирование/опцию удаления провайдера.
3. Подтвердите удаление. При необходимости очистите и сохранённый ключ именно этой ссылки через соответствующее действие редактора.
4. **Секрет в Numes при этом не отзывается автоматически**: если нужно, зайдите в Numes → Keys и удалите key. Иначе уже выданный ключ продолжит жить у других клиентов или в env.

### Ручной конфиг

Верните заранее сделанный `.before-numes` бэкап **на вашем профиле** либо удалите только блок `llm-pi-ai/providers.numes` и только запись `refs.NUMES_API_KEY`, сохранив остальные секции.

**Не заменяйте профиль целиком чужим конфигом.**

## Не нужен ли мне `numes run`?

`numes run opencode` / `numes run pi` — удобная документированная связка для **OpenCode, Pi OMP**, включая вставку или создание inference-ключа. **Для DSH это не установщик**. Читайте [Numes coding agents](https://numes.ai/docs/integrations/coding-agents). Обычное правило использования здесь:

```text
DSH → Settings → Models → Custom model API
Ещё один OpenCode/Pi-проект → numes run ...
```
